## 2026-11-15 要望の整理(P1〜P5)にともなう判断

- **読み(
  eading)を必須にする**: 単元プロンプトで、すべての語に読みを入れさせる(母語が日本語ならカナの近似、非ラテン文字の言語はローマ字も併記)。理由: 文字や発音に不慣れだと最初の語が読めない。出題画面(外国語→母語の4択)でも小さく表示し、設定 showReading で切り替える。音声→意味の問題では出さない(答えのヒントになるため)。
- **プロンプトの版**: APP_CONFIG.promptVersion を作り、骨組み・単元プロンプトの末尾に プロンプトの版: N を出す。取り込んだ単元の generatedBy に残す案は、スキーマ変更が要るため見送り。
- **初回の説明画面**: /intro を追加。kp.onboarded(localStorage)で視聴済みを記録。データなし・未視聴のとき、ホームから /intro へ移動する。
- **修正依頼プロンプト**: 取り込みエラー(JSON パスつき)から、AI に直してもらう依頼文を自動で作る(uildFixPrompt)。
- **解禁の方針(計画中・P5)**: 元の仕様の「ゆるいロック」を、「テストで解禁。ただし甘め、何度でも再挑戦、スキップ試験で先へも進める」に変える予定。しきい値は定数(UNLOCK_PASS_RATE)で、科学的な根拠はない。1人用のため A/B テストはせず、設定とデバッグの切り替えで調整する。
- **「定着」の基準(P2)**: 出題形式の決め方で既に使っている `MATURE_STABILITY_DAYS`(FSRS の安定度 10 日以上)を再利用する。新しい数値は作らない。研究にもとづく値ではなく、暫定。

## 2026-11-15 文字と発音のガイド(P4)のデータ形式

- **新しい取り込み形式 lang-study-guide(version 1)**: 第3のプロンプトで AI に作らせ、取り込む。理由: 文字や発音に不慣れだと、最初の語(例: selamat)が読めない。アプリには、発音の規則を同梱しない(教材の内容は AI が作る、という方針を保つ)。
- **保存**: content.guide(任意。対象言語ごとに1つ)。IndexedDB は、既存の singletons ストアに、キー guide で保存する(DB の版は上げない)。全体バックアップ(lang-study-data)の content にも含まれる。
- **形**: intro(導入の短い文)、sounds[](id、grapheme、
  eading、ipa、
  ote、examples[]、confusableWith[])、
  ules[](id、 itle、ody)。sounds の id と
  ules の id は重複不可。confusableWith は、同じガイド内の音のIDを指す。
- **練習**: 学習エンジン(FSRS)には載せない。ガイド専用の簡単な4択(/guide)にとどめる。理由: 音の知識は、単語の記憶とは別の性質で、まず「読める」ことを最短で確保したい。FSRS に載せるかは、使ってみてから決める。
- 取り込み後は erified: false。ユーザーが確認したらボタンで erified: true にできる(単元と同じ)。

## 2026-11-15 自己申告レベルと「試験でスキップ」(P4後半)
- **開始レベル profile.goal.startLevel(任意)**: eginner(初めて)/asic(少し分かる)/intermediate(かなり分かる)。省略時は eginner として扱う(既存データとの互換)。プロンプトの難易度の指示(骨組みの開始点、単元の語彙の範囲、ガイドの範囲)に使う。理由: 既に少し分かる人に易しい問題ばかりだと退屈になる。
- **試験でスキップ**: 単元の「試験でスキップ」は、その単元の語から最大8語を等間隔に選んで出題する(ステップ ID は {unitId}-skip、種類は unitTest)。SKIP_TEST_PASS_RATE(初期値 0.7)以上(最初の1回で正解した語の割合)なら、その単元を「クリア」にする: 全ステップを完了、全単語を導入済み、単元の状態を done。
- **合格しても復習の予定からは外さない**: 試験で出題されなかった語にも、FSRS の初期記録(評価 good)をつくり、後日の復習に送る(研究メモの方針: 「1回成功 → 後日に再出題」)。不合格なら何も完了にせず、何度でも再挑戦できる。しきい値(0.7)と出題数(8)は定数で、根拠はない暫定値。
