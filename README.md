# Kotoba Path(仮)

少数言語の学習アプリ(個人テスト版)です。ブラウザだけで動く、サーバーなしの静的サイトです。
最初の対象はマレー語、学習者の母語は日本語です。UI は日本語/英語に対応します。
データはすべてブラウザ内に保存し、プロフィール・教材・学習履歴には IndexedDB を使います。
JSON/CSV で書き出しができ、JSON の読み込みでバックアップを復元できます。
1日の目標や読み上げの設定には localStorage を使います。

## 公開手順(GitHub Pages)

1. リポジトリを GitHub に作って、このプロジェクトをプッシュします。
2. リポジトリの Settings → Pages → Source を **GitHub Actions** に変更します。
3. `main` にプッシュすると、[`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) が lint・テスト・ビルドを実行し、成功した成果物を公開します。
4. 公開 URL は `https://<ユーザー名>.github.io/<リポジトリ名>/` です。Actions の実行結果と公開先を確認します。
5. 画面の遷移は `#/` の形(HashRouter)です。公開先の `#/data` などへ移動し、再読み込みとアセットの読み込みを確認します。

`VITE_BASE` はビルド時の配信パスです。リポジトリ名が `kotoba-path` なら `/kotoba-path/` にします。
ワークフローはリポジトリ名からこの値を設定します。未指定時は `/` です。
ローカルでも同じパスで確認する場合は、ビルド前に設定します。

```powershell
$env:VITE_BASE = '/kotoba-path/'
npm run build
npm run preview
```

上の設定では、プレビューの URL にも `/kotoba-path/` を付けて開きます。

## 起動方法

リポジトリのルートで実行し、表示されたローカル URL を開きます。

```sh
npm install
npm run dev
```

### ビルドと確認

```sh
npm run build
npm run preview
```

`build` は TypeScript の確認と Vite のビルドを行い、`dist/` に出力します。
`preview` はそのビルド結果をローカルで確認するためのコマンドです。

### 品質チェック

```sh
npm run lint
npm run test
npm run format:check
npm run gen:schema
```

`gen:schema` は JSON Schema の再生成です。手動での確認項目は [docs/CHECKLIST.md](docs/CHECKLIST.md) にあります。

## 学習内容の作り方(プロンプトの流れ)

学習内容(単語・フレーズなど)は、別のチャットAIで作って取り込みます。
以下は教材を準備して学習する流れです。学習画面の実装状況は「既知の制限」を参照してください。

1. 初回アンケート(`/welcome`)で言語・目的・期限・目標レベルなどに答えます。
2. `/data` で「骨組みプロンプト」をコピーします。ファイルとしてダウンロードすることもできます。
3. 別のチャットAIに貼り付けて、コース全体の骨組みを JSON で出力させます。
4. `/data` の取り込み欄に JSON を貼り付け、「検証」で件数・警告・エラーを確認してから「取り込む」を押します。
5. 各単元の「単元プロンプト」も同じようにコピーし、AI が出した単元の JSON を検証して取り込みます。
6. ホームから単元とステップを選び、学習へ進みます。

1つの単元は 15〜25 項目を目安にし、多ければ A/B に分けて作ります。
取り込んだ内容は「未検証」(`verified: false`)です。内容を確認したら「確認済みにする」を押します。
**AI が作る内容の正確性は保証されません。** 要確認バッジが付いた内容は、信頼できる資料などで確認してください。
同じ単元を再取り込みするときは、追加・削除の差分を確認します。同じ ID の学習履歴(FSRS)は保持されます。

## データ形式の概要

全体の JSON は `format: "lang-study-data"`、`version: 1` を持ち、次の区分に分かれます。

- `meta`: アプリのバージョンや書き出し日時。
- `profile`: 言語、目的、期限、学習時間など。
- `plan`: 単元の骨組みと計画。
- `content`: 単語・フレーズ・例文・文法メモ。
- `progress`: FSRS、単元の進捗、XP、連続日数、学習履歴。

詳細は [docs/data-format.md](docs/data-format.md)、JSON Schema は [public/schema/](public/schema/) を参照してください。
AI の取り込み用 JSON は、骨組みが `lang-study-skeleton`、単元が `lang-study-unit` です。
ID は単語・フレーズがコース全体で一意で、単語は `言語コード:lemmaを小文字化して空白を-に`、同形異義は `~2`・`~3` を付けます。例文・文法メモは単元内で一意にします。

## バックアップ

`/data` から JSON/CSV を書き出せます。復元用には、プロフィール・教材・学習履歴を含む JSON を保管してください。
CSV は単語一覧の書き出し用で、Excel 向けに UTF-8 BOM を付けます。CSV の読み込みには対応していません。

JSON を戻すときは、`/data` の読み込み欄でファイルを選ぶか貼り付けて検証し、次の方法を選びます。

- **置き換え**: 確認後、保存データ全体を読み込んだ JSON に置き換えます。
- **統合**: 既存データに統合します。教材は読み込み側、FSRS は新しい復習、XP は大きい値を優先します。

Safari などでは、一定期間サイトを開かないと保存データが消えることがあります。
定期的に JSON を書き出し、ブラウザの外に保管してください。

## 画面の一覧

以下のパスは HashRouter の `#` より後に続きます。

- `/welcome`: 初回アンケート。
- `/`: ホーム。単元と学習状況の一覧。
- `/unit/:id`: 単元の詳細とステップ一覧。
- `/lesson/:unitId/:stepId`: レッスン用のルート。現在は単元・ステップ ID の仮表示。
- `/review`: 復習用のルート。現在は案内の仮表示。
- `/data`: プロンプト生成、教材の取り込み、書き出し、JSON の読み込み。
- `/settings`: UI 言語、1日の目標、学習日数/週、読み上げの設定。
- `/debug`: 設定の隠しリンクから開く開発用画面。現在は見出しのみ。

## 既知の制限

- マレー語の読み上げは、端末に対応する音声がないと使えません。その場合は音声の出題を行わない方針です。
- ローカルLLM接続は未実装です。設定画面は準備中で、接続先などの入力欄は無効です。
- 対応する出題形式のうち、ペアつなぎ(`match`)・書き取り(`listening`)は、レッスンにまだ組み込まれていません。
- レッスン・復習画面は仮表示で、画面上で出題から完了まで学習する機能は未接続です。
- デバッグ画面の仮想日付操作は未実装です。手動チェックリストには実装後の確認項目も含みます。
- サーバーなしのため、端末をまたぐ同期はありません。データの移動には JSON の書き出し・読み込みを使います。
